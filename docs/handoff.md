# 新会话交接与实施节奏

这是一套项目协作约定，不是 Codex 的官方轮数限制。任务状态、用户准备事项和当前换会话节点只维护在 [progress](planning/progress.md)；任务依赖只维护在 [implementation-plan](planning/implementation-plan.md)。本文件说明怎样交接，不另存会过期的当前任务清单。

## 什么时候换

默认一个新会话做约 3 轮实施，通常对应 2–3 个相关任务；可延长到 5 轮，在验收或有明确证据的子阶段结束时交接。复杂的存储、运行、审批任务可以单独使用一个会话。轮数是复盘提醒，不是为了换会话而提前关闭任务。

本次具体换会话节点见 progress。每轮由执行者主动给出“继续本会话 / 建议新会话”的结论和原因；出现反复忘记约束、重复调查、产品规划与实现混杂、模块目标明显改变时可提前交接。上下文压缩本身不代表实现已经变差，也不要求立即换会话。

## 怎么开

1. 在 Codex 的 Drov 项目下建立 New Chat，选择 **Local / 当前本地目录**，确认目录为 `/Users/yanlong/projects/drov`。当前工作尚未提交时，优先用这一目录。
2. 粘贴下面的交接 prompt。新会话先检查文件、Git 状态及验证证据，再确定下一项；无需复制全部聊天历史。
3. 如需改用另一 checkout/worktree，先核实提交、分支和文件确实包含交付内容；忽略目录中的环境与凭据不会因为项目相同而自动存在。不要同时让两个会话修改同一模块。

推荐在完整任务验收后保留 Git 提交作为可恢复检查点；真实 remote/CI 与账号准备见 progress。提交可以提供明确差异，不能替代测试。离线备份和 Git 都不应保存真实密钥。

## 可直接复制的 Prompt

```text
请在当前 Drov 项目中接续实施，不要只返回计划。

先阅读 AGENTS.md、docs/planning/progress.md、docs/planning/README.md 和 docs/handoff.md，检查当前目录、Git 变更、已有源码和最新验证记录。以 progress 为当前状态依据，以 implementation-plan 的前置依赖和验收条件选择下一项；若上一项尚未完整验收，先完成该项，不能直接跳过。

Drov 是 Python 通用 Agent 框架，能力范围对标 AgentScope 2.0；三个参考应用检验通用性，不构成产品业务边界。根据任务按需读取 API、运行契约、工程方案和 ADR。P4 已通过，不重新开启无具体缺项的一般规划轮，也不把后续功能预建成空壳。

在授权范围内主动实施、修复和验证。保护已有变更与品牌素材；发现影响接口/语义的冲突，同轮更新源契约、案例、测试和 ADR。缺少外部资源时，先完成不依赖它的工作，再明确说明需要我准备什么、何时需要、怎样安全配置；不要读取或输出真实密钥，不擅自调用付费模型、公开发布或部署。

结束前更新 progress 和本轮验证记录，区分实际完成、未完成及未验证范围。向我说明结果、重要限制、下一项具体任务及完成标准，主动列出需要我准备的仓库/账号/模型 ID/预算等条件，并给出是否应在下一轮开启 New Chat 的明确建议。无法在本轮完成的任务记录已验收子范围、剩余缺项和恢复步骤，不提前关闭整项。
```

## 每轮必须留下的交接信息

progress 应包含：完成项/验收证据、未完成子范围、下一项及依赖、具体用户准备事项与时点、Git/远程状态、下次换会话建议。验证记录包含实际环境、命令和通过/失败/未跑项；会改变接口的结论写入对应源文档/ADR。

这样新会话能从项目恢复工作依据，但不能保证完全复原旧聊天或消除错误。执行者必须检查源码与测试，不能将旧报告当作新变更已经通过的证据。
