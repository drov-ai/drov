# ADR-0036：评测单试验限额的停止范围

日期：2026-10-17。状态：已采纳；实际结果与恢复状态以 [progress](../planning/progress.md) 为准。

## 原因与选择

v10 正式第39项发生重复精确键读取，8次真实模型请求后仍缺最终回答；该试验按原规则失败，没有泄漏。所有费用已结算，但评测账本将单试验超限写为全批 stopped，导致42个独立试验无法执行。质量计划规定的是每试验8请求，模型质量失败本应保留在完整81分母里；全批停止应保护费用未知/总预算，不应把已结算的局部限额升级成全局停止。

新试验超限持久记录 `trial_stops[trial_label]=trial_model_limit`，拒绝该标签后续任何付费请求。原8个attempt、价格、费用及原13/11元上限不变。其他独立试验只有在无全局停止、所有费用settled且总预留允许时继续；pending/unknown/预算不足仍全局拒绝。报告明确该试验 `completion=incomplete` / `trial_stop`，其任务与schema保持失败，不补答、不重放、不剔除分母。

`trial_stops` 是开发评测账本的可选持久字段；旧账本没有它时按空处理，amend保留该字段与旧计数。**已存在的全局trial_model_limit不自动解除**：仍须新指纹、完整旧费用核对和显式reviewed_trial_limit登记。v10原39项/36通过及未执行42项保持原样，v11从新7+81开始，沿原575次/6.71037980元账本，不重新计算或退款。

只修开发评测限额范围；Pro/high/8192、提示、语料、oracle、预期、8请求/16工具及全部门槛不变。SDK的Run预算、公共API/状态、SQL、依赖没有变化。

## 替代方案与代价

- 提高单试验上限或跨进程重置计数：会放宽原门槛，不采用。
- 继续原失败试验、重抽或补成功答案：破坏固定样本，不采用。
- 因已结算的一个试验失败而停止所有剩余试验：混淆局部质量失败与全局费用保护，取代此旧行为。

代价是批次会继续消耗剩余独立试验的预算，仍由原全局费用预留逐请求限制。新增跨打开/跨登记的不可恢复局部限额、后续试验准入、pending阻断，以及实际driver完整81迭代的合成回归；合成driver结果明确offline，不作为真实质量。旧全局停止恢复/总预算/未知用量负向回归保持。
