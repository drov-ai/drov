# ADR-0004：首版范围、工程边界与维护策略

- 日期：2026-10-12
- 状态：P4 复核后纳入实施基线；未实现；控制与查看细化见 ADR-0005
- 关联：G-01 至 G-06、Q-API-08、C-01 至 C-19；细化 ADR-0002/0003

## 背景

P2 已定义统一内核与恢复语义，但首版若同时实现多 Agent、外部 Memory、多个模型/传输和调度，就难以验证每项保证。需要把通用产品地图收敛为完整而有限的交付范围，而不是限制为某类业务。

## 决定

- v0.1 包含单 Agent、Python 工具、基础 MCP、上下文/Memory、权限/HITL、持久化恢复、事件检查、HTTP 和工作台。多 Agent 延后；一级委派契约保留但 B-14 不算首期已通过。
- 单 Python 包 + 可选 extras，CPython 3.11 起，Pydantic 2；首个线上模型为 OpenAI Responses 适配，首个 MCP 传输为 stdio，官方 SDK v2。模型 ID 在实测时显式选择，不硬编码最新档位。
- SQLite 单连接、回滚日志、aiosqlite + 排他文件锁；Drov 在队列之上管理事务隔离及提交取消。无 Redis、多 worker 或外部 Memory 原子性承诺。
- 首期 Memory 采用最近记录/精确键/子串检索与显式工具写入；模型摘要、向量检索、后台自动提取后续独立引入。
- 澄清采用内置 HumanInput 工具描述，输入响应作为原调用结果；不恢复任意 Python 栈，也不重跑一个已经产生副作用的工具函数。
- 不默认自动删持久状态；显式维护、去重墓碑、未知副作用保留说明、恢复旧备份的人工 barrier 都是首版数据生命周期的一部分。
- 默认限额有明确值与失败行为；粗略 token 和费用必须标估算，不承诺金额硬上限。
- 先离线内核与故障验证，再适配真实模型；以实际验收安排版本。自有代码/文档工作选择 Apache-2.0，第三方代码逐项记录来源及许可；官网采用静态文档站，可与 alpha 同步公开。

## 替代与代价

- 首期复制完整成熟 Agent 框架：短期功能面多，但 Drov 很难独立解释和维护行为；选择复用底层 SDK/基础设施，自己负责公共契约和执行状态。
- 从只支持一个业务助手开始：验证集中，但不符合用户通用方向；使用三个案例检验同一内核。
- 全栈基础设施开箱启动：能支持更多部署模式，但增加首次安装与维护成本；单机能力清楚以后再扩展。
- 首期直接做语义 Memory、任意图和自动记忆：示例可能更亮眼，但检索评估、一致性和权限边界同时扩大；分期独立验证。
- 自动 TTL 或恢复旧备份后立即推进：操作更少，却可能丢失去重和外部执行事实；选择显式维护和保守核查。

代价包括首版模型/部署范围窄、Memory 检索能力基础、UI 初期不承诺扩展稳定、顺序执行吞吐有限。这些限制必须在 README/官网可见，不能宣传为所有 AgentScope 能力的完全替代。设计优势仍需任务与体验证据。
