# ADR-0034：研究评测的证据范围

日期：2026-10-17。状态：已采纳；真实评测结果以 [progress](../planning/progress.md) 为准。

## 原因与决定

T-16 v7 首项 S01-01 的事实、来源和 schema 正确，但 status 为 insufficient，原期望 sufficient，按预注册规则失败。独立复核发现题目泛问 A/B 的“重启保留能力”，语料只说明 A 所属进程重启后丢失与 B 是独立共享服务，没有说明 B 服务自身重启后的持久性；ResearchReport 也没有 B 重启字段。这是可定位的任务/输出范围缺项，不能据此断言模型失误或把旧期望改为 insufficient。

manifest v2 将 S01-01 明确为 A/B 的跨进程共享与 A 所属应用进程重启后的保留情况；ResearchReport 和评测说明明确充分性针对题目要求的事实。状态含义、相关来源、未知值、全文/预览/超时保持独立断言。合成资料、全部预期输出、数值 oracle、27/7/81 数量、8 请求/16 工具上限及发布门槛不变。已有真实 Runtime 回归增加错误状态、错误布尔值和未知事实臆测的负向评分检查。

新配置 v8 沿用 Pro/high/4096，避免同时更换模型；价格在新调用前按官方页面复核。先提交修订、登记新指纹，再沿原 13 元账本 amend，新目录完整 7 smoke 全通过后才正式 81。所有旧批次、失败和费用保留，不重算、补样或混分。

## 替代方案与代价

- 改旧期望为 insufficient：掩盖预注册失败且没有固定新任务范围，不采用。
- 补造 B 重启持久性或增加输出字段：引入不必要的新事实/任务，不能解决旧比较边界，不采用。
- 同配置换目录再抽首项：没有修复定义缺项，不采用。

代价是任务说明已在观察失败后澄清，属于自适应评测，不能声称盲测、原批次通过或单独证明模型改进。新批次与历史批次不是严格相同任务文本。仅改变开发评测，不改变通用 SDK、公共 API、运行状态、数据库或依赖边界；三个参考场景仍是通用性检验。
