# ADR-0013：首版 Python 代码沙箱与执行证据

日期：2026-10-14（Asia/Shanghai）。状态：用户已确认首版具备“生成并执行代码”；下面是待实施的工作决定，**沙箱 SDK 尚未实现/验收**。本决定形成时下一项为 T-09；当前实施状态和下一项统一见 [progress](../planning/progress.md)，基础容器资源准备不等于沙箱 SDK 验收。

## 原因

P4 初始基线将 Skill/沙箱留在后续范围，T-01 至 T-18 因而没有隔离代码执行的任务。用户本轮明确要求把代码生成与执行纳入首版，需要调整 C-17、任务依赖和发布验收。普通 Python 工具运行在宿主，并不提供任意模型代码的隔离边界；仅增加代码生成或 exec 工具不能满足该要求。

## 决定

1. 正式 v0.1.0 必交最小 Python 路径：现有 ModelAdapter 提出 code-only 工具调用，经既有权限/审批后在一次性隔离环境执行，真实有界结果回到同一 Agent 循环。先用 ScriptedModel 验证机制，T-11/T-16 验证真实模型生成代码与使用实际结果。Skill、持久 Notebook、多语言、联网/主机文件导入导出、云/更强隔离后端没有一并前移。
2. 首个后端采用应用显式配置的本地 Docker CLI/Engine、Linux 容器和预装固定 digest 的可信 Python 镜像。代码作为容器内固定 runner 的输入，不执行宿主 shell/exec/eval；固定非 root、有限资源、无网络/主机挂载/凭据/控制 socket，缺能力直接拒绝。核心安装/导入不要求 Docker，不增加云账号或真实模型调用。详细技术、数值及实际平台验证位置唯一在 [工程方案第 9 节](../planning/engineering.md)。
3. 拟议 PythonSandbox 按 write/policy（默认 ask）注册；宿主可显式 allow 或要求必需审批。审批绑定原代码、归属、revision、后端配置和限额；不能用计算审批代替另一工具的业务审批。后端依赖由 Runtime/ResourceBinding 装配，要求 SQLite 持久记录；公共字段与配置示例唯一在 [API 草案](../planning/api-draft.md)，当前不创建这些符号。
4. 派发前持久化稳定 execution_key 和预算/检查点；外部容器事实与 SQLite 提交分开。实际容器进程树/清理租约由 Runtime 持有；控制客户端结束不等于容器停止。结果可用且停止/销毁已确认才收尾；失去证据则核查并保留所有权/名额，不伪造 success/cancelled。已派发代码恢复不重跑，包括按键找不到容器的情况。取消后只核查/清理，不开启新模型或代码步骤；verify 保持只读。具体状态与内容投影唯一在 [运行契约第 13 节](../planning/runtime-contract.md)。
5. 保留已交付的 T-01…T-18 编号，插入 T-10A（闭环）和 T-10B（隔离/故障/恢复），顺序 T-09 → T-10 → T-10A → T-10B → 集成/评测/发布。两卡是首版门槛，不能仅因没有 Docker 或 mock 通过就关闭。HTTP/工作台/维护/文档/发布同步增加该路径，X-03 分阶段验收，不要求 T-10B 先完成后置 HTTP/UI。
6. 保留三类参考应用，各增加一个代码执行任务；增加 B-16/17 与真实容器专项矩阵。模型正式试验扩为 27 个任务×3 次，代码子组单独报告；离线隔离/恢复错误始终阻断正式发布，不能被平均模型分数豁免。数量、阈值和共同预算只维护在 [质量计划](../planning/quality-plan.md)。

## 替代方案与代价

- 仅在 T-18 之后实现：不符合用户确认的首版目标，取消此排期。
- 宿主线程/子进程或 AST 黑名单：无法证明文件、凭据、网络和资源隔离，不作为沙箱验收。
- 首版直接依赖云沙箱：需要服务账号/费用/代码外传及额外远端故障契约；留作后续后端。
- 首版强制 VM/所有平台、多语言和持久工作区：扩大隔离与恢复责任；当前选择最小可验证 Linux 容器路径。

容器依赖可信 daemon/内核和宿主维护，增加本地环境/镜像配置及专项 CI 成本；不是抵抗所有漏洞或敌对公网多租户的保证。普通应用 Python/MCP 工具仍由各自宿主执行。禁网络、无持久文件及不自动安装依赖会限制交互式编程任务；已有结果丢失时不能自动重算，用户需明确开始新的操作。是否支持 macOS/Windows 的 Linux VM 客户端由专项实测决定，不能继承 SDK 的平台成绩。

## 影响与恢复步骤

C-17 首版范围以及 API、运行/工程/架构、参考应用、质量、任务依赖、维护发布、导航/交接和 progress 同轮更新。本决定沿 ADR-0004/0005 首版工程/控制基线增加沙箱子范围，替代 P4 能力表/实施计划的沙箱后续排期；其他已验收任务不重开。P4 fingerprint 是历史快照，保持原文件不覆盖，后续语义差异通过本 ADR 和验证记录追溯。

本轮只交付文档，没有创建 SDK 空壳、迁移、schema 或可运行沙箱例子。T-09/T-10 先完成现有审批/未知结果/恢复；T-10A 前核实 Docker 服务、资源控制、镜像平台/digest/许可，固定实际版本，再依任务卡分批交付。外部资源缺失时先验收独立子范围，记录缺项与复现/恢复步骤，不提前关闭两卡或 T-18。Docker 官方文档依据及查阅日期见 [E-24 至 E-28](../planning/evidence.md)，文档机制不等于本项目实测。
