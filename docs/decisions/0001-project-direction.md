# ADR-0001：Drov 的产品方向与实施前工作方式

- 日期：2026-10-12
- 状态：已确认方向
- 依据：本次对话中用户的范围修正及“就按照你的建议开始产出对应的内容”的指示。

## 背景

用户计划长期维护开源 Agent 框架，兼顾实际使用、学习和工程能力展示，主要使用 Python。最初选择的业务系统助手场景随后被明确撤回；用户希望能力范围对标 AgentScope 2.0，适用于多种业务。

## 决定

1. Drov 定位为 Python 通用 Agent 框架，规划覆盖工具、MCP、Memory、权限、HITL、Tracing、持久化和完整应用服务。
2. 以渐进式 Python API、跨入口一致的运行机制、可检查的上下文与记忆作为优先验证的设计主张。本地工作台呈现这些能力。
3. 使用不同类型的官方参考应用检验抽象，不用单一业务限制产品。
4. 先建立产品定义、能力表、公共 API 草案和参考应用，再收敛架构、质量标准和实施任务。
5. 每轮更新仓库交接记录，并向用户给出下一轮工作建议；达到就绪标准后明确进入代码阶段。

## 暂不决定

具体 Python 最低版本、模型供应商、框架依赖组合、最终 PyPI 名称、许可证、部署服务、完整 v0.1 范围、稳定 API 字段及数据模型。

## 替代方案与取舍

- 聚焦单一业务 SDK：可以缩小初期范围，但不符合用户修正后的产品目标。
- 直接复制成熟框架并改名：可以快速获得表面功能，但独立价值、许可来源、上游同步和维护责任必须解决，不能作为默认方案。
- 一次性承诺与 AgentScope 所有功能完全等价：缺少实现与验证依据，且难以维护。采用能力地图和分阶段交付，公开标明支持范围。

## 后果

通用性需要跨场景验证；完整能力需要分层、可选集成和持续维护。产品主张不等于已证明优势。之后改变本决定时新增替代 ADR，保留本记录及其被替代状态。
