# ADR-0035：评测中的目标文件与缺失回答

日期：2026-10-17。状态：已采纳；具体评测结果以 [progress](../planning/progress.md) 为准。

## 原因与选择

T-16 v9 完整正式 73/81、schema72/75，但代码5/9未达门槛。两次 S02-09 实际原 summary.csv 与新进程 copied.csv 下载字节/hash 完全相同、授权拒绝正确；原 oracle 却以所有阶段全部产物数量必须等于2判定字节不变。额外的 PNG/建议表使它误判，题目和 manifest 没有“不得额外交付文件”的断言。另一次普通聊天无最终回答，评分器索引 None 抛 TypeError，掩盖了本可保留的零写入事实。

按原语义比较第一阶段唯一 summary.csv 与最后阶段唯一 copied.csv 的 hash；其他产物不参与这对目标文件计数。全部实际下载/ref hash、所需文件、数值、最终真实产物引用、跨进程、无授予拒绝仍检查。缺目标、重名目标、错误阶段或字节变化仍失败，不能仅比较数值。Memory 缺最终回答明确记录对应断言 false / schema false，同时保留实际安全事实，不用异常兜底丢掉检查。

代码说明改为按本题选择产物：只有题目要求图/建议表时才生成对应文件，避免全局说明引入无关工作。CSV/PNG/建议表已有格式要求不变。v9 三个响应恰好达到4096输出tokens并 incomplete（两次代码、一次普通聊天）；新候选输出8192，按既有机制同时绑定上下文/费用预留，保持 Pro/high、90s模型期限、8请求/16工具与全部门槛。

旧81项/八失败、用量/费用和报告不重算。新增离线诊断可说明 oracle 差异，不替代真实成绩；新源码提交、指纹登记后沿同一13元账本完整7+81。无 SDK/API/存储/依赖变化。

## 替代方案与代价

- 要求全部产物恰好两个：增加原题没有的限制，且全局代码说明曾要求图/建议表，不采用。
- 只比较统计值：无法证明原字节保留，不采用。
- 缺回答跳过 schema 或改算通过：掩盖真实失败，不采用。
- 用修复后的分数覆盖旧报告：破坏批次审计，不采用。

代价是见过失败后的多因素自适应修订，更高输出额度可能增加费用与耗时；不声称盲测、单变量提升或旧批次通过。真实用量仍按请求结算，预算不足/未知费用立即停止，不重建账本。
