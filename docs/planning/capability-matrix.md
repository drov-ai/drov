# 能力对标与 v0.1 范围

状态：P4 已复核首期范围；本表维护版本交付范围，不逐项维护实现状态。当前实施进度与验收证据以 [progress](progress.md) 为准；下面的必交范围不表示每一项已经实现。更新：2026-10-14。

AgentScope 列表示官方资料中可确认的覆盖，不表示质量排名或完全等价；来源标识见 [证据表](evidence.md)。版本基线主要为 2.0.9，E-05 是可变化的 main README。

下面是正式 v0.1.0 的工作交付范围：必交项全部验收才可正式发布；alpha 可只交付已完成部分并明确标识。实验性项也需功能验收，只是不承诺接口/界面长期稳定。后续项仍在通用产品方向内。实现与验收映射见 [实施任务](implementation-plan.md) 和 [质量计划](quality-plan.md)。

## 对标方法

P2/P3 的约束与取舍在 [架构](architecture.md)、[行为契约](runtime-contract.md) 和 ADR-0002/0003/0004 中记录。这些是 Drov 工作设计，不是已证明比竞品更好的地方。首版范围小于长期能力地图，但不限制用户业务类型。

1. 先比较可说明的任务和接口路径，标记原生支持、官方集成、用户自建或本轮未核实。
2. 实验阶段固定竞品发布版本、模型、工具数据、预算与成功定义。
3. 记录 Drov 与竞品各自的配置、行为和失败，不以文档篇幅或类名多少推断优劣。
4. v0.1 有限的支持范围不应被写成与 AgentScope 所有能力完全等价。

## 调整规则

新增或移出版本范围时，说明关联目标 G、受影响案例、维护成本和理由，并更新 [进度](progress.md)。公开测试版前，每个承诺条目应有实际实现和验收记录；只有接口设计的条目标记为计划或实验性。

2026-10-14 范围变更：用户确认首版具备“生成并执行代码”。C-17 的最小沙箱由后续前移为必交，尚未实现；工作决定见 [ADR-0013](../decisions/0013-first-release-code-sandbox.md)。原任务编号保留，新增 T-10A/T-10B 并接入首版发布依赖；更多沙箱深度和 Skill 没有随之扩大。

Drov 的容器机制依据为 E-24 至 E-28，记录在证据表；它们不是 AgentScope 竞品事实或 Drov 的运行验收。新增 C-17 对应 G-01 通用组合、G-03 入口一致、G-05 运行边界和 G-06 维护目标，仍通过原三个参考应用检验。

2026-10-14 第二次范围调整：用户采纳 [ADR-0016](../decisions/0016-sandbox-artifacts-and-backends.md)，将受控输入/持久产物加入首版必交，并增加独立可选 T-10C。前述 ADR-0013 的首次前移保留为历史；本次不是把 E2B、持久工作区或整个 AgentScope workspace 一起设为必交。新增成本为文件授权/存储/备份一致性、路径与容量边界、固定分析镜像以及可选远端验收；对应目标仍为 G-01/03/05/06。实现状态统一在 progress，当前两种后端的 SDK 能力都未实现。
