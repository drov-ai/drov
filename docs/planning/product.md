## 定位

Drov 是面向 Python 开发者的通用 Agent 框架。目标是在一套可理解的概念下覆盖构建、运行、调试和服务化，并允许从简单调用逐步扩展到有状态、可交互、可观测的应用。

能力范围主要对标 AgentScope 2.0。对标能力不意味着兼容其 Python API，也不意味着首个版本支持所有模型、场景和部署拓扑。

## 用户与使用方式

- 个人开发者：在脚本、Notebook 或现有 Python 程序中嵌入 Agent。
- 应用开发者：接入工具、知识和记忆，构建对话或任务型产品。
- 后端团队：将 Agent 服务化，接入已有身份系统、数据库和观测设施。

官方案例覆盖检索报告、跨会话助手和审批操作。它们是验证样本，不是三个限定业务，也不代表已有真实用户需求数据。

## 设计原则

### 渐进使用

基础调用提供默认配置；持久化、Memory、权限和服务化按需加入。便捷默认值不得隐藏是否持久化、是否产生外部写入、何时读取记忆等重要行为。

### 核心执行规则一致

SDK、命令行、本地工作台和 HTTP 服务使用同一运行内核。入口负责传输与展示，不独立实现第二套 Agent 循环。跨入口一致不等于不同模型调用会得到逐字相同的答案。

### 上下文有来源

区分会话历史、当前模型输入、跨会话记忆、外部知识与运行状态。记录内容来源和处理过程；模型内部未公开的推理过程不属于可检查范围。记录粒度、脱敏和保留策略必须可控。

### 可组合和可替换

模型、存储、Memory、观测和服务集成在明确边界替换。先实现必要适配器，不提前抽象每一种可能后端。扩展设计要包含资源所有权和关闭行为。

### 默认体验完整

本地开发能够运行示例、查看事件、处理审批、定位错误。完整服务作为可选组合交付；仅使用 SDK 不必启动完整基础设施。

## 差异化假设

| 标识 | 假设 | 需要的验证 |
| --- | --- | --- |
| H-01 | 渐进接口降低接入成本 | 相同场景下比较概念数、必须配置项、首次跑通过程；不能仅比较代码行数 |
| H-02 | 同一内核降低服务化迁移成本 | 对照 SDK、HTTP 和 UI 的行为用例与迁移改动 |
| H-03 | 上下文检查降低排错成本 | 预置记忆漏用、内容截断、来源混淆案例，让使用者定位原因 |
| H-04 | 本地工作台缩短首次验证路径 | 记录干净环境中的依赖、启动步骤及可完成任务 |

这些假设可能被证伪。测试不支持时，应调整设计或宣传，而不是选择性报告。

## 阶段性边界

- 通用框架不能承诺对任意任务有效，也不能从工具审批推导出操作系统级隔离。
- 先明确支持的运行与部署范围；分布式高可用、通用流程编辑器和完整插件市场属于后续候选能力。
- 首版纳入模型生成 Python、受控文件输入、隔离执行、有界实际文本与可持久读取产物的完整路径；运行权限与隔离均需验证，不把语言回答或宿主线程执行算作沙箱交付。
- Docker 为首版默认必交，E2B 为首期系列独立可选适配，缺资源不阻塞本地版本；多 Agent、工作流、Skill、持久 Notebook 与其他更深后端按独立场景引入；一级委派仍为 v0.2 候选。首版不因增加代码执行而变成某一种业务应用，详见能力表。
- 复用官方 SDK、成熟基础库及有来源的设计；独立负责 Drov 的公共契约和集成质量。
- 不通过更换名词制造差异，不默认引入难以解释的全局注册、隐式共享记忆或后台自动操作。

## 成功的证据

短期看同一个 API 体系能否覆盖三个案例，边界是否可解释，用户能否独立跑通。中期看真实使用、缺陷解决和持续回归。求职与学习成果来自可解释的设计、可复现的验证和真实贡献，不用品牌包装或功能数量替代。
