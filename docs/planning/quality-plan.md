# 质量与评估计划

状态：T-01 至 T-04 类型/存储/注册与生命周期检查已通过，见 [T-04 验证](../validation/t04-runtime.md)；本文件的 Agent 运行/故障/模型测试及分数仍待后续任务产生。更新：2026-10-13。

本文件维护测试层次、夹具、判定和报告要求；需求定义仍在 [参考案例](reference-scenarios.md) 与 [行为契约](runtime-contract.md)。任务顺序在 [实施任务](implementation-plan.md)。通过模型任务不替代运行时正确性，通过离线替身也不证明模型会选择正确工具。

## 1. 分层验证与门槛

| 层次 | 测什么 / 工具 | 运行时机 | 通过条件 |
| --- | --- | --- | --- |
| L0 文档与静态 | 链接、编号、例子语法、格式、类型、包导入边界 | 每次相关修改 | 所有适用检查通过；公共类型示例能在已实现版本导入 |
| L1 确定性契约 | pytest + pytest-asyncio；ScriptedModel、可控时钟、计数工具 | 每个相关任务 / PR | 适用 S/X/B 的断言全通过；不使用真实 Key、不依赖公网 |
| L2 真实本地集成 | 临时 SQLite 文件、两个独立进程、stdio MCP、ASGI 和真实本地 HTTP/SSE | 对应集成任务 / 发布候选 | 事务、锁、作用域、断连、重启和关闭通过；不能用全 mock 冒充 |
| L3 故障与竞态 | 明确边界注入失败、子进程硬终止、并发响应、取消竞争 | 触及状态/存储修改 / 发布候选 | 不多执行写入、不越权、不产生无依据成功；未知结果按约定暂停 |
| L4 真实模型任务 | 固定数据、规则评分、人工复核 | 手动授权环境；不在普通 PR 自动付费 | 达到下述质量门槛，报告模型/参数/费用/失败；不省略失败样本 |
| L5 使用与发布 | 干净 wheel 安装、三个示例、工作台浏览器流程、外部开发者试用 | alpha/rc/正式版本 | 文档路径可运行；关键流程全通过；体验假设单独记录 |

不设置为了好看而刷满的覆盖率。状态、权限、事务与外部调用边界必须有成功、拒绝、失败和恢复断言；覆盖率用来找盲区，不能替代这些清单。新失败必须留下最小复现与回归用例，非确定性失败不能靠重跑转绿掩盖。

## 2. 固定夹具

| 夹具 | 内容 | 能检验什么 |

| ResourceSpy | 自有/借用连接、启动中失败、拒绝取消的受控工具 | 关闭顺序、ShutdownIncomplete 和锁仍被持有 |

T-02 已创建 tests/fixtures.py 的 ScriptedAdapter：预期输入、预定流、异常及关闭标记；测试仅验证归一协议，完整 ScriptedModel 运行循环在 T-06 接入。T-03 已有 SQL 提交边界/取消屏障、真实独立进程锁与硬终止夹具，验证数据库一致性；不当作外部事项服务副作用实验。T-04 增加 ResourceSpy、工厂/关闭屏障、等待者取消、拒绝停止的任务、实际可释放线程及资源/SQLite 锁联合验证；B-06/07/12 只覆盖私有调度、注册与所有权部分。真实工具线程执行器、审批恢复和 MCP/HTTP 仍待对应任务。其余夹具仍待创建。真实进程崩溃使用子进程中的屏障通知“已到目标边界”，父进程再终止并重启；持久计数服务活在另一个进程，避免把待验证的副作用和 Agent 同时清零。线程不可终止案例也隔离在可回收的测试进程内，不让 CI 永久挂起。

默认限额的边界值、非 JSON 数值、超大输入/结果、取消与完成竞争、数据库提交取消、保存响应后尚未推进时崩溃，都属于上述 L1–L3。核查 unresolved 必须换新请求接受后续证据，旧回执仍去重；Memory 删除后可读墓碑版本并重建。特别检查：写入已执行但结果不可序列化/过大时不能假装未执行，也不能因转换异常自动重做。

P4 补充的必要边界同样必须实现为测试，不能只检查正常路径：

- T-03/T-06/T-07（B-02/03/15）：start 同键重试返回原引用；失败/取消后的下一 Run 只读一次用户输入，工具调用组完整，未派发/未知标记不变成成功；不完整模型流不入历史。
- T-09/T-10（B-04/05/07）：槽位满或 revision 缺失不消费响应；resume 不返回旧审批；响应消费、取消与崩溃组合；撤权不复用已接受批准。verify 不消费请求，迟到建议不能推进旧请求，取消/限额之后只核查不重写；无可用输出但效果已核实的取消仍可收尾。
- T-05/T-06/T-13（B-10/11）：只读元数据、只响应、可读正文三类身份分别访问结果/交互/事件/context；便利入口在副作用前拒绝缺权限者，订阅中撤权停止正文；include_content=False 不含 token、参数、Memory key/content。
- T-04/T-10（B-05/12）：零重试合法、负数非法；耗尽时间/步骤后已知边界失败，未知写入仍核查；未停止旧调用仍占资源，不因 suspended 释放槽位或锁；失败/取消的已知与未知用量如实保留。
- T-03/T-15（B-02/07/10/11）：清理不使旧请求再执行；完整 Session 墓碑不可隐式重建；恢复 barrier 经重启仍生效，包含备份之后缺失的 Run/去重键；未补齐独立事实不得解除；abandonment 始终保留未知说明。

## 5. 真实模型评测

首版准备每场景 8 个固定任务，共 24 个任务；每个固定配置运行 3 次，共 72 个独立试验。S-02 一个试验含保存和新进程读取两个阶段，S-03 可含模拟人类响应；**72 个试验不等于 72 次模型调用**。变体及事实断言在看结果前提交，合成资料不放真实业务/个人数据。普通离线 CI 对全部任务用脚本替身跑通结构，真实结果另存。

固定任务的构造范围如下。T-16 将其落成带输入/资料/工具结果、控制步骤、预期状态、事实断言及 schema 适用标记的 manifest，在第一次真实调用前锁定语料 hash；当前表不是已经生成的数据集。

| 场景 | 8 个预定变体 | 必须事先写下的预期 |
| --- | --- | --- |
| S-01 | 资料齐全；问题改写；资料不足；混入无关来源；长结果截断；来源版本冲突；检索超时；资料含越权指令 | 结论/引用对应真正读到的资料；冲突和不足明确；超时不伪造检索成功，资料指令不改变工具权限 |
| S-02 | 明确保存后重启读取；更新版本；删除后新会话查询；跨用户/租户/Agent 隔离组；required 超时；best_effort 超时；写入失败；未要求保存的普通对话 | 内容/版本/事务事件与回答一致；隔离组全部通过才算该试验通过；required 超时模型调用为 0；迟到内容不注入，普通对话不自行声称保存 |
| S-03 | 批准；拒绝；缺输入后澄清；重复批准；派发前撤权；审批期间重启；写入响应丢失；未知效果时取消 | 正确目标/参数、审批顺序、工具独立计数；恢复不多写，未知不猜测；取消核查后不启动新 Agent 动作 |

第一批先执行 6 个 smoke 试验，确认适配器、价格与评分无误，再执行完整 72 项试验；smoke 不混入正式分数。两者合计最多 78 个试验，共用一次批准的费用上限；T-11 的 smoke 也计入这 6 项，不另开账本。真实调用前由用户提供可访问的服务/model ID、项目密钥配置以及总预算；未获得预算不运行付费批次。建议首轮讨论上限为等值 US$10，**只是建议，不是已授权支出**。每试验最多 8 个逻辑模型请求及 16 次工具派发，重试和多阶段成本计入同一试验账本；超过预算标记 incomplete，不把未执行样本算成功。预算是否足够需实际估算；不足时申请新的批次预算或调整下一批配置，不能截去失败样本冒充完整结果。

报告使用当时固定模型 ID/快照、供应商参数、SDK 版本、语料 hash、Drov commit、OS/Python/SQLite、配置和时间；无法固定供应商快照时注明。计费依据当时官方价格、输入/输出/缓存用量；未知用量/成本标 unknown 并停止下一付费试验等待核实，不以 0 补齐。运行中费用只是估算，不能保证供应商结算绝对不超预算，需留余量。

v0.1 正式发布门槛（alpha 可公开未达标结果和限制）：

- 运行时安全与一致性：不得出现越权、重复非幂等写入或无依据的持久化成功；任一失败阻塞发布，无平均分豁免。
- 最终输出 schema 有效率至少 95%，分母 N_struct 是 manifest 预先指定需要最终类型化输出的正式试验数；至少 ceil(0.95 × N_struct) 项有效。预期在模型前失败或只收尾为 cancelled 的试验标 N/A，不当作 schema 成功。原本要求最终输出却出现错误、拒绝、超时的试验仍在此分母中；工具参数有效率另报，不混入最终输出指标。
- 任务全断言通过至少 85%，每场景至少 80%。完整 72 试验至少 62 项通过，每场景 24 项至少 20 项通过；预期安全拒绝/失败只有满足预注册全部断言才算任务通过。未执行项不算通过，批次未跑全则 incomplete；服务大面积不可用也保留本批记录，完整重跑后另报，不能只挑成功结果。
- Memory 任务同时看保存事实、读取事实和回答使用；审批任务同时看最终状态、工具参数与独立服务的副作用计数。纯语言自述不计为证据。
- 每次失败人工复核；成功样本每场景抽查至少 3 个。首期不依赖 LLM-as-judge 作为唯一裁决，评分争议进入报告。

这些门槛是用于首版改进的工作目标，并非统计证明。报告展示原始分子/分母、按场景结果、重试、延迟 p50/p95、用量与成本；72 个试验不足以宣称对所有业务有效或领先竞品。阈值若需调整须在新一轮实验前说明理由，保留旧结果。

## 6. 差异化与使用体验

H-01/H-02/H-03/H-04 分别记录接入步骤和概念、服务化改动、预置故障定位、本地首次运行。发布前由维护者在干净环境完整走一遍；尽量邀请至少 2 位未参与实现的 Python 开发者使用同一说明独立完成三项任务。没有参与者时标记“仅维护者验证”，不阻塞 alpha，但不能宣称已经证明易用性领先。

竞品对照另设实验：固定 AgentScope 发布版本、模型、预算、工具数据与任务，记录其原生支持、官方集成或补写部分，测量接入与定位过程；本次文档研究不能当作基准成绩。只因 API 更短或换类名不判优势。Pi 仅在适合的同类任务中比较，不强行给不同定位的产品排总榜。

## 7. CI 与验收记录

每个 PR 执行 L0/L1；相关模块执行 L2，状态/存储修改执行 L3。Linux 覆盖 Python 3.11–3.14；macOS/Windows 至少各覆盖 3.11 与 3.14 的锁、进程恢复、MCP 关闭和安装用例。完整矩阵在 rc 执行；不能把未跑平台写成通过。新 Python 版本先在单独探测任务运行。

provider 协议测试使用本地 HTTP 替身或脱敏自有夹具，不需要 Key；外部真实模型标记 live，默认排除，手工触发且有预算。发布需测试 SDK-only、各 extra 和组合 extras 的 wheel 安装，以及 sdist 重建时工作台资产存在。UI 用浏览器端到端检查关键交互，不只做截图。

每个实现任务关闭时记录：commit/版本、需求编号、运行环境、检查命令、通过/失败/跳过及原因、产物路径、未解决限制。报告按实际生成内容建立链接，当前不创建假报告。未来回放分三种标签：只展示记录、再次请求模型、再次执行工具；默认查看和回放绝不重做外部写入。
