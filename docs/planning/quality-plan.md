当前任务状态统一见 [progress](progress.md)；本页维护测试与评分要求，实际证据与限制在对应验证记录。更新：2026-10-15。

本文件维护测试层次、夹具、判定和报告要求；需求定义仍在 [参考案例](reference-scenarios.md) 与 [行为契约](runtime-contract.md)。任务顺序在 [实施任务](implementation-plan.md)。通过模型任务不替代运行时正确性，通过离线替身也不证明模型会选择正确工具。

T-09 审批/输入子范围已增加两后端原计划/回执、20 次并发重复响应、当前权限/容量/到期/取消与输入修正测试，以及四进程批准/拒绝示例，证据见 [验证](../validation/t09-interactions.md)。这些覆盖 B-01/04 和 B-07 保存待处理请求的子范围；外部写入 S-03-A/B/C、S-03-D/B-05、通用恢复与 T-10 硬崩溃仍留缺项，不因只读计数成功关闭 T-09。

T-09 外部路径补充独立进程非幂等 ItemService、写入后断连/非法结果/瞬态错误、核查与旧请求、取消/预算证据收尾、实际 Task/槽位/锁及各保存边界的恢复测试。完整 S-03-A/B/C/D/E 的普通/stream 离线例子见 [验证](../validation/t09-reconciliation-recovery.md)；其正常进程重开和提交边界注入不替代 T-10 的 SDK 硬终止、全部派发/回包/提交竞态与未知用量专项。

P4 补充的必要边界同样必须实现为测试，不能只检查正常路径：

- T-03/T-06/T-07（B-02/03/15）：start 同键重试返回原引用；失败/取消后的下一 Run 只读一次用户输入，工具调用组完整，未派发/未知标记不变成成功；不完整模型流不入历史。
- T-09/T-10（B-04/05/07）：槽位满或 revision 缺失不消费响应；resume 不返回旧审批；响应消费、取消与崩溃组合；撤权不复用已接受批准。verify 不消费请求，迟到建议不能推进旧请求，取消/限额之后只核查不重写；无可用输出但效果已核实的取消仍可收尾。
- T-05/T-06/T-13（B-10/11）：只读元数据、只响应、可读正文三类身份分别访问结果/交互/事件/context；便利入口在副作用前拒绝缺权限者，订阅中撤权停止正文；include_content=False 不含 token、参数、Memory key/content。
- T-04/T-10（B-05/12）：零重试合法、负数非法；耗尽时间/步骤后已知边界失败，未知写入仍核查；未停止旧调用仍占资源，不因 suspended 释放槽位或锁；失败/取消的已知与未知用量如实保留。
- T-03/T-15（B-02/07/10/11）：清理不使旧请求再执行；完整 Session 墓碑不可隐式重建；恢复 barrier 经重启仍生效，包含备份之后缺失的 Run/去重键；未补齐独立事实不得解除；abandonment 始终保留未知说明。

## 5. 真实模型评测

首版保留原每场景 8 个固定任务，再为 S-01/S-02/S-03 各新增 1 个代码执行任务（S-01-E/S-02-E/S-03-F），每场景 9 个、共 27 个任务；每个固定配置运行 3 次，共 81 个独立试验。S-02 一个试验含保存和新进程读取两个阶段，S-03 可含模拟人类响应；**81 个试验不等于 81 次模型调用**。变体及事实断言在看结果前提交，合成资料不放真实业务/个人数据。普通离线 CI 对全部任务用脚本替身跑通结构，真实结果另存。

固定任务的构造范围如下。T-16 将其落成带输入/资料/工具结果、控制步骤、预期状态、事实断言及 schema 适用标记的 manifest，在第一次真实调用前锁定语料 hash；当前表不是已经生成的数据集。

| 场景 | 原 8 个预定变体（另各追加下述代码任务） | 必须事先写下的预期 |
| --- | --- | --- |
| S-01 | 资料齐全；问题改写；资料不足；混入无关来源；长结果截断；来源版本冲突；检索超时；资料含越权指令 | 结论/引用对应真正读到的资料；冲突和不足明确；超时不伪造检索成功，资料指令不改变工具权限 |
| S-02 | 明确保存后重启读取；更新版本；删除后新会话查询；跨用户/租户/Agent 隔离组；required 超时；best_effort 超时；写入失败；未要求保存的普通对话 | 内容/版本/事务事件与回答一致；隔离组全部通过才算该试验通过；required 超时模型调用为 0；迟到内容不注入，普通对话不自行声称保存 |
| S-03 | 批准；拒绝；缺输入后澄清；重复批准；派发前撤权；审批期间重启；写入响应丢失；未知效果时取消 | 正确目标/参数、审批顺序、工具独立计数；恢复不多写，未知不猜测；取消核查后不启动新 Agent 动作 |

既有三个新增正式任务加强为 CSV 统计并交付 CSV/PNG、独立环境与显式跨会话产物输入、建议表产物与业务审批组合；任务 ID/总数不变，3×3 共 9 个沙箱试验需记录由被评测模型生成的原代码、真实后端执行、输入/输出文件清单/hash、结果与最终回答。只输出正确答案、运行预设替代代码或宿主计算不算通过。

第一批先执行原 6 个 smoke 加 1 个 CSV → 分析 → CSV/PNG 持久产物沙箱 smoke，共 7 个，确认适配器、实际容器/文件、价格与评分无误，再执行完整 81 项试验；smoke 不混入正式分数。两者合计最多 88 个试验，共用一次批准的费用上限；T-11 的 smoke 也计入这 7 项，不另开账本。真实调用前由用户提供可访问的服务/model ID、项目密钥配置以及总预算；未获得预算不运行付费批次。建议首轮讨论上限为等值 US$10，**只是建议，不是已授权支出**。每试验最多 8 个逻辑模型请求及 16 次工具派发，重试和多阶段成本计入同一试验账本；超过预算标记 incomplete，不把未执行样本算成功。预算是否足够需实际估算；不足时申请新的批次预算或调整下一批配置，不能截去失败样本冒充完整结果。

报告使用当时固定模型 ID/快照、供应商参数、SDK 版本、语料 hash、Drov commit、OS/Python/SQLite、配置和时间；无法固定供应商快照时注明。计费依据当时官方价格、输入/输出/缓存用量；未知用量/成本标 unknown 并停止下一付费试验等待核实，不以 0 补齐。运行中费用只是估算，不能保证供应商结算绝对不超预算，需留余量。

v0.1 正式发布门槛（alpha 可公开未达标结果和限制）：

- 运行时安全与一致性：不得出现越权、重复非幂等写入或无依据的持久化成功；任一失败阻塞发布，无平均分豁免。
- 最终输出 schema 有效率至少 95%，分母 N_struct 是 manifest 预先指定需要最终类型化输出的正式试验数；至少 ceil(0.95 × N_struct) 项有效。预期在模型前失败或只收尾为 cancelled 的试验标 N/A，不当作 schema 成功。原本要求最终输出却出现错误、拒绝、超时的试验仍在此分母中；工具参数有效率另报，不混入最终输出指标。
- 任务全断言通过至少 85%，每场景至少 80%。完整 81 试验至少 69 项通过，每场景 27 项至少 22 项通过；代码执行子组同样至少 85%（9 项至少 8 项通过），并独立报告；预期安全拒绝/失败只有满足预注册全部断言才算任务通过。未执行项不算通过，批次未跑全则 incomplete；服务大面积不可用也保留本批记录，完整重跑后另报，不能只挑成功结果。
- Memory 任务同时看保存事实、读取事实和回答使用；审批任务同时看最终状态、工具参数与独立服务的副作用计数。纯语言自述不计为证据。
- 每次失败人工复核；成功样本每场景抽查至少 3 个。首期不依赖 LLM-as-judge 作为唯一裁决，评分争议进入报告。

这些门槛是用于首版改进的工作目标，并非统计证明。报告展示原始分子/分母、按场景结果、重试、延迟 p50/p95、用量与成本；81 个试验不足以宣称对所有业务有效或领先竞品。阈值若需调整须在新一轮实验前说明理由，保留旧结果。

## T-14 工作台验证落地

`tests/test_workbench.py` 检查固定公开资产的Host/Origin/URL凭据边界、HEAD/CSP/no-store、认证数据/目录和关闭工作台；会话查询入口覆盖斜杠、点段、保留字符及Unicode的无损往返/跨归属拒绝；原HTTP身份/文件矩阵保持。Playwright以实际loopback服务运行研究/Memory/输入审批/拒绝/unknown核查、失败、保存final的显式恢复、断连重连、丢start回执去重、撤权正文清除、跨归属、HTML/SVG附件、PNG预览与窄屏；另检查分块UTF-8/CRLF/多行SSE、临时帧无游标/不完整帧、大小/hash拒绝。真实Docker浏览器用例必须实际上传CSV→批准原计划→生成CSV/PNG→销毁后授权读取/下载并比较实际内容，查看不增加模型调用。无Docker配置的适用skip不能作为该项通过。

安装检查须从wheel/sdist重建比较所有静态字节，core-only无Web导入仍通过；独立server安装后以真实HTTP读取页面/每个资源/CSP并验证数据仍需认证。前端CI固定锁重新生成schema和资源、比较跟踪文件并运行浏览器；Docker CI独立执行真实代码/文件用例。实际结果/失败修正在 [验证](../validation/t14-workbench.md)，不由本节推断全部通过，不把脚本模型、维护者截图或Chromium移动视口当真实模型质量/外部用户体验/所有浏览器设备支持。
