## 1. 数据记录与查看

| 数据 | 默认保存/导出 | 查看与后续清理 |
| --- | --- | --- |
| Runtime 持久状态 | 必须保存输入、消息、工具参数/结果、检查点、交互与归属，以及恢复必需协议数据 | 同一 scope 的授权用户；正文另受 view_content 权限控制 |
| ContextManifest | 保存来源/版本、取舍与估算；恢复必需的确定输入有本地内容引用 | 元数据默认可按权限查看；正文不能随普通 trace 自动外发 |
| 内置 Memory | content、版本、来源和墓碑；必须主动工具写入 | forget 仅影响当前可检索记忆；历史清理是独立操作 |
| Artifact / Sandbox lease（T-10A 已实现） | 不可变字节/hash/类型/大小、原归属/来源、Run 授予/引用、暂存/容量/执行租约；字节在配对私有 store，不塞 JSON | 元数据 read，名称/字节另受 view_content；未 ready 暂存不可下载；物理路径/云 URL/凭据不展示 |
| 日志/导出 | 默认只记录 ID、状态、错误码、耗时、已知用量等元数据；外部 exporter 默认关闭 | 正文导出需要明确配置与权限；适用应用提供的 redactor |
| 临时 token 增量 | 不作为持久恢复日志保存 | 断连可丢；完整已提交消息按持久状态规则处理 |
| 密钥与连接 | 不写入消息/检查点/导出；环境变量或应用凭据服务提供 | 记录非秘密引用；恢复时重新解析 |

普通 Python 日志禁用原始请求/响应 dump；供应商异常原文可能含内容，转为结构化错误码和脱敏摘要。redactor 作用于展示/导出副本，不默默修改恢复记录。密钥模式匹配不可能识别全部敏感正文；应用负责工具返回和输入的数据边界，Drov 不宣称自动脱敏能覆盖任意业务数据。

view_content 覆盖 SDK 结果、HTTP 快照、持久化事件、临时 token、交互 prompt/参数、上下文及新增 Artifact 名称/字节/预览/下载；不只保护 get_context。默认元数据投影、便利入口权限预检及运行中撤权的规范位置为 [行为契约第 6 节](runtime-contract.md)。T-05 定义权限，T-06 起各入口落实，T-13 验证 HTTP，T-15 检查导出；不能等到发布维护阶段才补权限。

本地存储不是加密数据库，也不是操作系统沙箱。初始化尽量采用仅当前用户可访问权限，工作台需要认证；产品文档明确备份、文件权限和磁盘保护由宿主管理。raw protocol items 不作为 UI 思维链显示。

## 2. 保留、清理与备份

默认不自动过期删除持久状态/Memory，不在后台悄悄破坏恢复能力；CLI/文档必须明确“保留至显式清理”。首版提供**离线维护**，Runtime 停止后取得同一所有权锁，先给 dry-run 记录数量、范围、依赖关系和受影响的恢复能力，再执行指定范围。不得在普通 HTTP 请求中自动迁移或大规模删库。

首期清理单元为完整 Session 及其 Run/事件/交互/上下文；独立 Memory scope 可选择同时删除。普通清理拒绝包含未结束运行、未核清副作用或仍在执行的本地调用；新增沙箱的未确认停止/销毁租约同样受保护，SDK 进程死亡不证明后端容器已结束。若确需放弃一个无法继续的运行，要先显式记录 abandonment 原因并将其以 failed/data_abandoned 终结，附未知操作仍未核实的事实和不可恢复标记；这是放弃推进，不是宣称外部未执行。该特殊管理动作要求应用管理员权限，离线维护前必须确认原进程已停止。随后如清理正文，墓碑仍保留未知 operation_id、工具身份和放弃原因，报告不声称操作已核实。

归属与去重元数据和正文分开：清理留下最小 tombstone（运行/会话标识、终态、不可恢复原因、scope 和 request_key 的带密钥摘要，不留输入正文）。相同旧 request_key 返回 Gone/410，不生成新任务；已清理 Session ID 也不隐式重建，新的会话必须使用新 ID。查询已清理记录返回内容不可用。去重墓碑默认不自动到期。应用若要连墓碑/整个数据库一起销毁，维护工具明确提示旧去重保证随之消失，客户端不得重用旧请求键。墓碑摘要密钥由存储元数据管理，不从模型上下文取得。

要完整删除某用户的历史内容，应清理其所有相关 Session、Memory、导出与备份；memory.forget 不等于上述删除。物理磁盘擦除、外部备份和供应商数据删除不属于 SQLite 行删除的保证。已发出的模型输入无法从本地撤回。

备份在停止 Runtime、取得维护锁后通过 SQLite backup API 完成，并记录版本/时间/校验和；恢复验证 schema 与完整性，不能自动重做写入。恢复旧备份会回退去重与操作记录，包括完全不在备份中的新 Run：必须核对备份之后的外部操作，不能只因为旧库显示未派发就立即执行。首版维护工具对恢复的整个存储设置人工 recovery barrier，阻止 start 和所有新外部派发，查看/维护可用；核查并补齐必要的去重/操作事实后由管理员解除，没有独立证据则继续阻断。

删除/维护策略引入的 tombstone、data_abandoned、恢复 barrier 是 P3 对 P2 的细化，相关行为同步到 runtime-contract 和 ADR-0004。未来定时 TTL 清理须复用这些保护，不能另起规则。

## 3. 版本与兼容

T-10A 第二批的实际增量见 ADR-0018：core records/user_version=1 不改，显式 ArtifactStore 配对启用 artifact_schema=1 与两张扩展表；新版读旧库，旧 SDK 会拒绝扩展库，不能混用或仅复制 SQLite/字节之一。Artifact 来源枚举进入 ContextManifest v2，无文件仍 v1，新版兼容 v1/v2，未知版本/boolean 拒绝。完整扩展/字节/台账备份与回收仍待 T-15，不从单个输入重开测试推断完整备份安全。

ADR-0020 增加显式 sandbox_schema=1 / sandbox_leases 表及 active 索引，仅装配沙箱资源时启用；records DDL/user_version/record schema=1 不改。新 SDK 可读旧普通库；旧 SDK 拒绝未知扩展，禁止降级写入扩展库。Run 无沙箱时不写 sandbox_bindings，旧接收摘要保持；沙箱 Run 固定非秘密 backend hash/config 与 ArtifactStore，恢复需原配置。lease 与原阶段/观察/销毁证据必须随数据库和私有字节共同保留。T-10B 扩展真实硬终止验证，T-15 实施完整维护/迁移/barrier，不由当前恢复夹具推断物理断电安全。

Python 发布使用 0.1.0aN → 0.1.0bN → 0.1.0rcN → 0.1.0 的预发布路径；Git tag 使用 v 前缀。预发布可以只覆盖已完成能力，必须附支持表；正式 v0.1.0 需要能力表中全部必交项和质量门槛通过。实验性工作台仍需功能验收，但不承诺 UI 扩展接口稳定。

0.x 内按以下项目约定维护，不以“还没 1.0”为由无提示破坏用户：

- 补丁版本不故意破坏公共签名、结果字段、事件和存储兼容；修复错误引起行为变化必须在变更记录说明。
- 不兼容改变只在次版本进行，给迁移说明；能提供兼容层时至少保留一个次版本并发出弃用提示。
- 包版本、record schema、event schema、Agent revision 分别管理；功能实现改变时开发者更新 Agent revision，不能靠版本字符串猜测函数体兼容。
- 读取更新的未知 schema 时停止写入并给明确不兼容错误；能安全展示的通用元数据可只读，不假装可恢复。
- 新增可选事件字段可在相同 schema 主版本内兼容；改变含义、删除字段或改枚举需版本变更。状态字段不得用“未知则 completed”的方式兼容。

数据库迁移是离线显式操作：取得锁 → 备份 → 核对源/目标版本和活动运行兼容 → 事务迁移 → 完整性检查。首版 schema=1 仍需测试拒绝未来版本、合成旧版本迁移和中断回滚；不能因只有一个版本就不设边界。降级不自动改库，恢复备份按上节 barrier 处理。真实迁移需求到来时使用实际历史 fixture 补充。

## 4. 许可与上游复用

Drov 自有代码与文档采用 Apache-2.0，T-01 已加入标准 [LICENSE](../../LICENSE) 和 [第三方来源记录](../../THIRD_PARTY.md)；品牌素材另列来源和使用说明，不据此默认授权他人冒用项目标识。已有品牌文件保持不变并排除在 Python 构件外。依据为 [Apache 官方许可文本 E-22](evidence.md)，这里是工程流程选择，不作特定上游组合的法律结论。

复用分开记录：

| 方式 | 所需记录 | 对外表述 |
| --- | --- | --- |
| 思想/接口借鉴 | 官方设计/文档链接，采纳内容与 Drov 取舍 | 明确灵感来源，不把常见模式包装成原创发明 |
| 作为依赖调用 | 包名、版本/锁、许可、用途；构件中保留适用声明 | 说明集成边界，依赖能力不算 Drov 自己重写 |
| 复制/修改源码 | 仓库/文件/commit、原许可和版权声明、改动范围、NOTICE 等要求 | 在具体文件和第三方记录中保留归属，不能只在聊天说“参考过” |

T-01 已建立 THIRD_PARTY 记录，当前未复制其他 Agent 框架源码；随依赖/复制实际发生更新，构建产物检查必要声明。先优先正常依赖成熟基础库，独立实现 Drov 的状态、接口与组合契约。来源/许可不明的片段不纳入发布；这不妨碍继续自有实现。仓库分发包、前端资源与文档素材分别检查，不能仅检查 Python 依赖。

## 5. 发布与官网

T-17 先产出能本地查看的官网和文档，再办理公开托管：

1. 站点包括定位、快速入门、三个例子、能力/限制表、运行原理、API、排错、版本记录和贡献入口。首页展示当前真实版本；API 教程按相同发布版本验证。
2. MkDocs 构建静态产物，由 Cloudflare Pages 托管；配置版本、构建指令与输出目录均在仓库记录。构建预览使用合成示例，无模型 Key；Python 服务另由使用者运行。
3. 官网可与首个公开 alpha 同时上线，明确 alpha 范围；不必等 1.0，也不把预发布宣传成生产成熟。维护文档使用稳定链接，至少保留已发布版本的源快照及其包版本对应关系。
4. 正式发布走：锁定候选 commit → CI/安装/评测证据 → wheel/sdist 与校验和 → TestPyPI 演练 → PyPI 正式构件 → GitHub Release 与同版本文档。TestPyPI 未成功不能写“发布验证通过”；能离线完成的部分先完成。
5. PyPI 优先 Trusted Publishing/OIDC；不把长效发布 token 放仓库。官网域名和发布身份单独核验，当前不执行上传、域名绑定或外部发布。

账号能力以实际配置为准，不假定用户创建组织就已配置包权限或工作流。[E-20/21](evidence.md) 支持静态构建与身份机制，未证明本项目已部署。

发布后每个 release 回答：用户遇到什么问题、现在如何改善、兼容性影响、验证范围、已知限制。功能不足可以发布明确范围的 alpha，不能把门槛改成“先发了再说”。回滚网站可回到已验证静态构件；软件包不覆盖同版本，修复用新版本。安装回退还须核对数据库 schema，不能直接降级覆盖数据。

## 7. 首版沙箱的维护与发布边界

首版代码沙箱是 C-17 必交项；T-18 的正式发布必须有 T-10A/T-10B、X-03、B-16/17/18 的真实执行/受控输入/CSV与PNG持久产物/隔离/故障及安装证据。没有 daemon/镜像只阻塞真实子范围，不阻塞 T-09/其他独立离线工作；不能仅以协议替身或 SDK 包安装通过关闭沙箱卡。代码/输出/工作空间属于用户内容，正文保留与授权沿本策略；停止并销毁容器不删除旧记录/备份，不宣称物理擦除保证。

离线维护处理带执行键/后端归属的租约与 tombstone；后端连接不可用时不能以“查不到”核销仍可能存在的容器。恢复旧备份须核对备份后的执行键/派发/独立后端证据，recovery barrier 阻止原代码重派发。资源丢失/仍活动/清理不明分别说明，不把 data_abandoned 当资源已清理；备份不复制运行中的容器或宣称能恢复 Python 进程。

受信镜像、预装 Python/库与系统组件的来源、版本/digest/许可在 T-10A 实际选择时登记；未选定不填假 hash、未验证不宣称镜像可用。CI 或官网不能承诺容器抵抗所有内核漏洞/公网敌对多租户攻击；首版不默认下载镜像、上传代码至云服务或开通云沙箱账号。构件/镜像公开发布仍须相应授权，首版功能进入计划不构成公开部署授权。

### Artifact 保留与一致备份

输入与产物保留至显式清理，名称/内容与权限沿原正文规则；Memory.forget、容器销毁及输出引用未被模型采用都不删除文件。完整 Session 清理先删除该 Session 的授予/引用；同一内容仍被另一 Session、输入快照、操作或活动执行/暂存租约引用时，不删除字节，保留原来源的最小归属事实。只有最后合法引用已清理且无活动租约，才将 Artifact 置为已清理并返回 Gone/410，ID 不复用；删除原 Session 不隐式取消另一 Session 已合法取得的不可变引用。跨 scope 不共享可观察的去重或存在性。普通正文导出不默认包含文件，显式文件导出逐项 read/view_content，使用受控逻辑名/ID，不泄露本地路径或云控制 ID。

未 ready 暂存/失败接收/上传需记录归属、大小、阶段、持有租约及期限，包含在容量中；离线 dry-run 展示回收候选与依赖。只有确认无活动写者/执行、无引用并持有维护锁时才删除；中断回收有恢复台账，不能删除字节后仍声称 ready 可读。未确认资源或 data_abandoned 的未知清理义务继续保留；查不到远端资源不自动核销。输入被执行复制后，本地撤权/删除不能承诺撤回已传的数据。

停止 Runtime 并取得同一维护锁后，备份 SQLite 与相配 ArtifactStore、已提交清单/字节校验和/配对标识；检查每个 ready 引用可核对，未完成快照不发布为可恢复备份。恢复先校验版本/引用/字节/配对，缺失或损坏不变成成功下载；恢复整个存储仍设 recovery barrier，保护备份后丢失的派发/去重/资源/Artifact 事实。输入和产物可备份，容器/VM/Notebook 进程不在备份中。新增记录/DDL 的实际扩展见 ADR-0018/0020 及生成参考，完整迁移/备份 fixture 由 T-15 落地。

### 可选 E2B 的构件与费用

T-10C 不作为不含 E2B 的 Docker v0.1 发布前置；未完成 adapter 可从公开构件/安装 extra 排除并明确“计划”。若构件公开提供 e2b extra，则真实远端/安装/许可/费用与 B-17/18 及声明 profile 的边界证据必须通过，不能把实验性当作免验收。状态/支持平台/模板版本明确记录，不继承 Docker CI 成绩。T-13/T-14 接入同一 Runtime，无需另建云业务界面；选定 E2B 的跨 HTTP/UI 声明仍需对应入口实测。

云调用前单独授权服务、账号/区域/template、允许上传资料和沙箱总预算（含失败/必要收尾预留），与模型预算分别记账；只用合成资料开始。凭据仅宿主安全引用，日志不 dump provider 正文或密钥。远端停止/销毁是运行资源事实，不保证供应商保留副本或物理擦除；上传前核对实际服务的数据/保留条件。无账号或费用条件不阻塞 Docker 实施，不能擅自创建云资源、调用付费模型、公开镜像/extra 或部署。

ADR-0023 兼容补充：只有显式 E2B 绑定启用 sandbox_schema=2；表 DDL 沿v1，增加远端事实的payload。旧 SDK 在 open 拒绝2，新 SDK 可读取旧Docker v1；单独Docker不升级、序列化不加远端字段，已有v2不降级。E2B凭据/原模板build/预算ID及价格假设的非秘密配置随租约备份，真实Key独立安全保存。预算是按完整寿命累计的保守准入，不等同于实付余额/赠金资格，跨SQLite与模板构建需独立宿主总账；区域为项目声明，当前SDK无法证明驻留，强区域配置拒绝。实际证据和剩余发布条件见progress/T-10C验证。


T-13 按 [ADR-0025](../decisions/0025-http-identity-and-uploads.md) 在带ArtifactStore的服务显式启用独立upload_schema=1。旧SDK因未知扩展表拒绝打开且不得改库；原records/Artifact/Sandbox DDL与版本未变。HTTP暂存receiving/staged/consumed均须进入T-15备份/回收审查：原SQLite+bytes+消费事实共同保留；过期未消费只允许持排他锁的显式维护回收，不自动删除；已消费字节视同原输入，不能按上传TTL清除或重新授予另一Run。服务当前无清理/迁移HTTP路由。

T-15 首批落地补充（[ADR-0027](../decisions/0027-offline-session-retention.md)）：当前离线入口仅完成数据库逻辑清理与墓碑、共享来源证明和累计费用保留；首次删除启用独立retention_schema=1，原库仅预览不升级，旧SDK拒绝扩展库。bytes_reclaimed=0，阶段字节、stage.json的逻辑名与容量仍保留，不能宣称完整个人数据删除或实际回收。已销毁E2B租约的预算预留转存到按预算ID的HMAC索引金额，新的准入同时计入该金额；原未确认租约不能删除。前述完整回收、abandonment、一致备份/恢复/barrier、实际迁移和导出规则仍是T-15后续验收，不从本批测试推断已实现。实际子范围/下一步统一见progress。
